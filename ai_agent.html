Lilian Weng 经典 Agent 拓扑架构

源自前 OpenAI 研究副总裁 Lilian Weng（翁荔）2023 年开创性论文《LLM Powered Autonomous Agents》的“螃蟹架构图”。

🦀

经典理论出处：Lilian Weng (翁荔) · LLM Powered Autonomous Agents

Agent (LLM) 居中当大脑，向四周延伸出 Planning（规划）、Memory（记忆）、Tools（工具）、Action（行动） 4 大核心器官。

权威理论基石

💡 一句话总结：大模型是脑细胞（Brain），而 Planning（规划拆解）+ Memory（记忆召回）+ Tools（工具扩展）+ Action（执行交互） 共同构成了自主 Agent 的完备结构。

Agent 的四大核心能力图谱

聊天式 AI 只有「对话大脑」，Agent 则具备推理规划、环境交互、工具调用与状态记忆构成的完备能力体系。

1. 推理与规划 (Reasoning & Planning)

基于 LLM 进行逻辑链推演 (CoT / ReAct)。将复杂的大目标拆解为串行/并行微型步骤，遇到障碍时动态调整后续执行策略。

2. 状态与记忆 (State & Memory)

记录长流程中的中间变量、工具执行历史与环境反馈。结合 Context Window 短期记忆与向量库 (RAG) 长期记忆，多轮迭代不迷路。

3. 工具调用 (Tools Execution)

打破纯对话输入框！扩展外部能力延伸，自主选择并调用 Web 搜索、Python 执行环境、数据库与第三方 API。

4. 环境交互与反思 (Action & Reflect)

感知真实环境输入（API 返回、终端报错），对环境产生真实副作用（修改代码、发邮件），并根据 Observe 结果自愈纠错。

💡 核心结论：大模型是脑细胞，而 Agent 是将推理、规划、工具与环境闭环组合在一起的整车装配结构。

Planning - Action - Observe 控制循环

普通 LLM 是单向问答（Input ➔ Output）；Agent 是闭环自愈系统（Input ➔ [Plan ➔ Act ➔ Observe] × N ➔ Output）。

⚙️ 真实案例演练：自动修复代码报错并部署

Planning 规划
步骤 1：分析任务与制定方案
目标：修复 server.py 报错。计划先调用终端命令 pytest 捕获准确的失败堆栈。
Action 行动
步骤 2：环境交互与工具调用
执行工具命令：run_terminal("pytest test_auth.py")
Observe 观察
步骤 3：捕获真实环境反馈
终端返回报错：NameError: name 'jwt' is not defined on line 42
Planning 调整
步骤 4：根据 Observe 反思并调整策略
发现缺少引用，计划读取 server.py 并在头部补全 import jwt。
Action 行动
步骤 5：再次修改文件并运行验证
自动写入代码修补，并重新触发测试命令 pytest。
Observe 交付
步骤 6：测试通过，交付结果
环境返回 3 passed in 0.4s！Agent 确认完成，交付修改总结。

Agent 核心落地场景全景图

打破单纯对话框限制，在研发自愈、商业分析、企业合规审查与个人 Copilot 领域全面落地。

1. 研发与运维 (DevOps & SRE)

• 跨语言/框架代码重构：AST 解析 ➔ API 替换 ➔ 自动化构建校验
• 线上故障诊断自愈：告警触发 ➔ 查日志追踪链路 ➔ 执行降级并通知

2. 商业分析与 BI (Data Analyst)

• 连库自主 SQL 探索：业务追问 ➔ 动态生成并执行 SQL ➔ 关联挖掘
• 自动化可视化报告：Python (Pandas) 分析 ➔ 导出图表与分析报告

3. 企业业务自动化 (Enterprise Ops)

• 发票/合同跨系统对账：OCR 识别 ➔ 比对 ERP 订单 ➔ 发现差异并核实
• 二级复杂客服处理：调物流/仓储 API ➔ 规则判断 ➔ 原路退款并致歉

4. 深度调研与 Copilot (Research & Assist)

• 竞品深度追踪：自主浏览全网 ➔ 抓取官网/财报 ➔ 交叉验证生成 SWOT
• 多 API 行程/会议规划：日历冲突规避 ➔ 酒店/航班比价 ➔ 自动预订

💡 场景共同点：不依赖硬编码路线，目标明确、路径未知，需通过工具调用 + 环境反馈自主探索交付。

黄金判定法则：你的业务适合做 AI Agent 吗？

避免盲目套用概念！通过 3 大关键维度 与 控制权归属矩阵 精准评估落地可行性。

AI Agent 可行性三大硬性指标

1. 🔧 工具可感知性 (Tool Availability)
是否有明确的 API、Shell 终端、数据库或 DOM 接口可供 Agent 调取并作用于真实环境。
2. 🔄 过程容错与自愈性 (Fault Tolerance)
中间步骤是否允许“试错”。Agent 的本质是探索反馈，环境报错能够作为新的 Observe 信号。
3. 🎯 结果判定客观性 (Objective Criteria)
人类或代码是否拥有确切的最终验收标准（如：测试全绿、SQL正常返回、导出的表格格式规范）。

控制权归属：AI 工作流 vs AI Agent

对比维度 AI 工作流 (Workflow) AI Agent (智能体)
控制核心 程序员硬编码 If/Else LLM 大脑动态决策
执行路线 确定性单向/分支流水线 [Plan-Act-Obs] × N 闭环
异常处理 抛出 Error / 预设中断 抓取报错并自主修正

⚖️ 落地决策建议：流程完全确定且不允许试错 ➔ 选择 AI 工作流；目标确定但路径未知、需要环境反馈与容错自愈 ➔ 选择 AI Agent。
