大模型排版机制解密

🟢 Markdown 格式 (最省 Token)
| 姓名 | 年龄 | 岗位 |
|---|---|---|
| 张三 | 28 | 算法工程师 |
| 李四 | 32 | 深度学习专家 |
• 字符数：约 90 字符
• Token 消耗：仅 35~45 Token
• 优势：无冗余闭合标签，流式推流不会中断破版。
🔴 HTML 格式 (极为臃肿)
<table><thead><tr>
  <th>姓名</th><th>岗位</th>
</tr></thead><tbody>
  <tr><td>张三</td>...</tr>
</tbody></table>
• 字符数：约 260 字符
• Token 消耗：高昂 130~160 Token
• 💥 差距：比 Markdown 多耗 3 ~ 4 倍 Token！
🟠 JSON / JS 结构格式
[
  {"name":"张三", "age":28},
  {"name":"李四", "age":32}
]
• 字符数：约 150 字符
• Token 消耗：70~85 Token
• 差距：引号与键名重复，Token 比 MD 高出 80%+。
💡 为什么多耗 Token 会摧毁用户体验？
① API 费用乘以 3：模型按 Token 计费，HTML 吐字直接导致成本暴涨。
② 打字机推流极慢：模型每秒只能输出 30~50 Token。吐 40 个 Token 只需 1 秒，吐 160 个 HTML Token 需要 4 秒！
③ 语法崩塌风险：HTML 缺少一个 `
` 就会摧毁整个前端 DOM 布局；Markdown 标记具有独立前缀性，天然适合流式推流。

LaTeX、Word、PDF 的后台语言源码剖析

揭开排版格式的底层面纱：为什么 AI 选 LaTeX 算公式，却绝不直接生成 Word XML 或 PDF 坐标？

📐 LaTeX (学术与数学公式首选)
\documentclass{article}
\begin{document}
已知勾股定理：
\[ a^2 + b^2 = c^2 \]
求积分：\int_{a}^{b} f(x)dx
\end{document}
• 本质：诞生于 1980 年代的学术论文排版语言。
• 大模型用法：Markdown 无法表示复杂分式与矩阵，AI 遇到公式输出 $$a^2+b^2=c^2$$，前端使用 KaTeX 渲染。
📄 Word (.docx 底层 OOXML)
<w:p>
  <w:r>
    <w:rPr><w:b/></w:rPr>
    <w:t>这是加粗文本</w:t>
  </w:r>
</w:p>
• 本质：把 .docx 解压后发现其实是庞大的 XML 压缩包！
• 淘汰原因：极其臃肿！为输出 6 个字要吐几十行 XML 样式 ID，95% 算力全浪费在废字上。
📕 PDF (绝对坐标 PostScript)
2 0 obj
<< /Length 64 >>
stream
  BT /F1 12 Tf
  72 712 Td (Hello World) Tj ET
endstream
• 本质：PDF 不是文本格式，而是低级矢量画笔绝对坐标指令！
• 淘汰原因：`72 712 Td` 代表在纸张 X=72 Y=712 画字。PDF 是绝对坐标绘图指令，LLM 无法在二维空间算坐标。
